## 2. 閱讀模組規格（`read` 路由，先做這個）

### 2.1 文章來源（純前端可行性）

| 來源 | 做法 | CORS | 判定 |
|---|---|---|---|
| A 自編每日短文 | `data/read/daily.js`：60 篇（N5×20、N4×20、N3×20），每篇 150–400 字＋3 題理解題；依 `App.today()` 取 `日序 % 篇數` | 無 | **主力，第一版必做** |
| B NHK NEWS WEB EASY | 只放「今日去讀」外連＋「讀完回來貼全文」；不抓、不轉載 | 對方無 ACAO，fetch 必失敗 | 只做連結 |

| D 貼網址 | 先 `fetch(url,{mode:'cors'})`，3 秒失敗就顯示「這網站不讓網頁直接讀，請用書籤小工具或複製全文」 | 多數失敗 | 做，但要誠實降級 |
| E 書籤小工具 | `javascript:` 書籤：取 `<article>`/最長 `<p>` 群 → `window.open(本站+'#read-in')` 並 `postMessage({title,url,text})`；本站 `message` 監聽只收 `type:'jpq-read'` 且長度 ≤50,000 | 繞過（在原站執行） | 桌機可用；手機 Chrome 需從網址列輸入書籤名，Safari 可用；說明頁附 3 張圖 |

不做：公用 CORS proxy（隱私外洩、不穩）、自架後端（違反純前端）。

### 2.2 斷詞＋離線字典（`js/jp-text.js`，全域 `JPText`）
- **字典＝現成資料**：`MIND.lex.N5…N1`（8,034 詞，列 `[jp,kana,zh,pos,grp,…]`，lex 合計約 495KB）＋ SCENES vocab（13×34）＋ CARDS。啟動時建 `Map<表層形, entry>`，key 同時放 jp 與 kana。
- **活用還原**：用既有 `MIND.conjugate(jp, grp)`（data/mind/conj.js，8.9KB）對每個動詞／形容詞展開 masu/te/ta/nai/pot/pass/caus/vol/ba/tara 等形 → 反查表（表層形 → 辞書形）。約 2,500 動詞×20 形 ≈ 5 萬鍵，首次建表 <300ms，存 `App.idb` 快取。
- **斷詞演算法**：逐字最長匹配（上限 8 字）；查不到時依字種切段（連續漢字／片假名／平假名）；助詞 は が を に で と も へ の から まで 單獨切。未知漢字詞標 `?`，點擊顯示「字典沒有，可自填中文」。
- **Token**：`{s 表層, b 辞書形, r 讀音, p 詞性, lv, zh, i 位置}`。注音三段切換：全部／只漢字／不顯示（`<ruby>`）。
- **進階包（第二版，選配）**：kuromoji.js＋dict（gz 約 17MB，待實測），設定頁手動下載、Web Worker 執行；第一版不做。
- 載入：`App.lazy([['read',…]], ['data/mind/conj.js','data/mind/lex-n5.js',…,'data/mind/grammar.js','js/jp-text.js','js/read.js'])`；N1/N2 lex 只在文章出現未知詞時才載。

### 2.3 點詞加字卡（接 Tracker）
- 點詞 → 底部抽屜：大字、讀音、羅馬字（`JPText.romaji`）、中文、等級、🔊（`App.speak`）、**＋加入字卡**＝`App.trackBtn(item)`。
- item：`App.wordItem({jp:b, kana:r, romaji, zh, hint:'出自《標題》：所在句'}, '📖 閱讀', 'word')` → id `word:<辞書形>`，與場景字合併不重複。
- 長按／拖選多字 → 「加整句」→ `phrase:<句子>`。已加入的詞在文中加底線色（`Tracker.has`）。
- `source` 固定 3 種：`📖 閱讀`、`🧩 片語`、`📐 文法`（review.js 依 source 分組，不可用文章標題）。

### 2.4 文末「本文片語／文法」偵測規則
- **文法**：從 MIND.gram 的 `pat` 產生比對器：去括號註解（`の（所屬）`→`の`）、`〜`＝任意前接、`／`＝或；只收**長度 ≥2 的句型**（略過單字助詞は/が/を，避免洗版），並以 token 邊界確認（如 `〜ている` 需前一 token 為動詞 te 形）。依 `lv` 排序，每篇最多 12 條，顯示 pat、zh、conn、**本文原句高亮**、＋字卡（id 沿用 `gram:<句型>`，source `📐 文法`）。
- **片語**：①CARDS idiom＋SCENES phrases 全字串比對；②名詞＋を/に/が＋動詞 的連續 token（如「電車に乗る」）出現 → 收為搭配；③慣用句尾（`〜てください`、`〜ことになる`、`〜について`）由文法表重用。每篇最多 10 條，id `phrase:<辞書形片語>`。
- 一鍵「全部加入字卡」（silent 加入，結束 toast 共 N 筆）。

### 2.5 UI 流程
```
首頁 📰 讀文章 → read 書架
 ├ 今日短文（自編，已讀✔）→ 閱讀器
 ├ NHK Easy 今日（外連）→ 回來「貼上全文」
 ├ ＋貼文章（貼全文｜貼網址｜書籤小工具說明）→ 閱讀器
 └ 我的文章（IndexedDB，最近 50 篇）
閱讀器：頂列[注音 全/漢/無][🔊全文][字級] → 內文（點詞=抽屜）
       → 文末：本文文法 N 條｜本文片語 N 條｜生字 N 個（全部加入）
       → 理解題 3 題（自編文才有）→ App.reward('read:<id>', 星數)
```
- 存放：全文與 tokens 存 `App.idb`（key `doc:<雜湊>`），**不進 App.state、不上雲**；`App.state.read={done:{id:1}, last}`。
- 獎勵：讀到底＋點過 ≥1 詞 → `App.reward`（同篇只首次全額，符合 CONTRACT XP 規則）。每日任務加「讀 1 篇」。
- 驗收：375px 下貼 1,000 字文章 1 秒內可點；離線（飛航模式）自編文可讀；加入的詞出現在不會清單「📖 閱讀」分組。

## 3. 歌曲跟唱規格（`song` 路由）
- **版權**：本站不收錄任何有版權歌詞／音檔。內建示範只放公有領域童謠 3 首（如「さくらさくら」「ふるさと」「うさぎとかめ」，作者歿逾 70 年且 1967 前歿者，待逐首查證）。
- **新增歌曲**：貼歌詞（每行一句）＋音源三選一：①YouTube 網址（`youtube-nocookie.com/embed` iframe＋IFrame Player API，可視區 ≥200×200、不遮蓋）②本機音檔 `<input type=file accept=audio/*>`（Blob 存 IDB）③無音源＝TTS 朗讀。只存本機，不上雲、不匯出歌詞。
- **對時**：「打點模式」：播放中每句開始按一下 → 記 `t[i]`；可微調 ±0.2s。之後播放 `timeupdate`（本機）／250ms 輪詢 `getCurrentTime()`（YouTube）→ **逐句高亮＋自動捲動**。
- **注音切換**：歌詞過 `JPText.tokenize` → ruby 全／漢字／無；點詞同閱讀器可加字卡（source `🎵 歌曲`）。
- **A-B 循環**：點句子設 A、再點設 B，或「單句循環」；到 B `seekTo(A)`。
- **慢速**：本機 `audio.playbackRate` 0.5/0.75/1；YouTube `setPlaybackRate`（依影片支援）；TTS 用 `App.speak(jp, 0.7)`。
- **填空**：依程度挖空該行 N5–N4 詞（1–2 個／行），選項或輸入假名；錯的加 Tracker。
- **錄音跟唱**：`getUserMedia`＋`MediaRecorder` 錄當前句 → 立刻並排播放「原曲該句／我的」；有 `SpeechRecognition`（js/town.js:93 已有偵測）時轉文字比對假名相似度給 1–3 星。錄音只存記憶體，離開即丟。
- 資料：IDB `song:<id>`＝`{title, src:{yt|blob|tts}, lines:[{jp, t}], at}`。
