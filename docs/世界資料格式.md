# 世界資料格式（地區 → 街區 → 店內）

冒險模式的所有地圖與店家都是資料，放在 `data/world/`。引擎是 `js/world.js`，句型在 `js/phrase.js`。
寫完一律跑 `node tools/check-world.mjs`（可加檔名只檢查該檔），**0 個錯誤才算完成**。範例看 `data/world/tokyo-1.js`。

## 檔案
- `data/world/index.js`：地區清單（`WORLD.regions`），每個地區列出要載入的檔案 `files` 與街區順序 `order`。
- `data/world/<檔名>.js`：一個檔案 = 一次 `WORLD.pack('<地區id>', { districts:[…], shops:[…] })`。同一地區可拆多個檔。

## 街區 district
```js
{ id:'ueno', name:'上野', jp:'上野', kana:'うえの', icon:'🐼',
  desc:'一句中文介紹（旅程第幾天、來這裡做什麼）',
  map:[ '…', '…' ],        // 每列等長；寬 9–11、高 9–13
  start:[x,y],             // 進入街區時站的位置，必須是可走的格子（x 由左 0 起、y 由上 0 起）
  places:{ K:{…}, S:{…} } }
```
地圖字元：`=` 馬路（可走）、`.` 人行道／廣場（可走）、`#` 建築（裝飾）、`^` 樹／公園、`~` 水、空白 = 空地；
**其餘字元（英數字）= `places` 的 key**。同一個字母連續多格 = 一棟大建築。每個 place 至少要有一格上下左右緊鄰可走格，且從 `start` 走得到。

place 類型：
| type | 欄位 | 說明 |
|---|---|---|
| `shop` | `shop:'<店id>'` | 可進入的店（圖示、名稱取自店資料） |
| `gate` | `icon,name,jp,kana` | 車站／巴士站／機場，點了可前往同地區其他街區或回日本地圖。**每個街區恰好 1 個** |
| `spot` | `icon,name,jp,kana,tip`，可加 `say:{jp,kana,zh}` | 景點：文化小知識＋一句現場用得到的話（例：請人幫忙拍照） |
| `sign` | `jp,kana,zh`，可加 `style`、`note` | 路上的看板／標誌。`style`：y 車站黃、g 綠、b 藍、r 禁止紅、k 黑、w 白、o 橘、p 粉 |
| `npc` | `icon,name,jp,kana,lines:[{jp,kana,zh}]` | 路人（引擎會拿來出「聽指路走到目的地」任務），`lines` 2–3 句閒聊 |

每個街區：3–5 間 shop、1 個 gate、1–3 個 spot、1–2 個 sign、1 個 npc。

## 店 shop
```js
{ id:'ueno-konbini',            // 全世界唯一，小寫英數與 -
  kind:'store',                 // store 自己拿商品去結帳｜eat 入座點餐｜service 櫃台服務（飯店、車站、機場、租借…）
  scene:'konbini',              // 對應舊場景（konbini ramen cafe drugstore izakaya clothes directions station hotel shrine airport emergency yakiniku），沒有就 null。每個 scene 全世界只能用一次
  icon:'🏪', name:'便利商店', jp:'コンビニ', kana:'こんびに',
  desc:'一句中文介紹', tips:['禮儀／文化提醒，3–6 條，真實、具體'],
  map:[ … ], start:[x,y],
  zones:{…}, items:[…], asks:[…], acts:[…], may:[…], info:[…], quests:[…], dialogues:[…] }
```

### 店內地圖 map
每列等長；寬 7–11、高 7–11。`#` 牆、`.` 地板（可走）、`+` 出口（**恰好 1 個，在最外圈**）；**其餘字元 = `zones` 的 key**。
同一字母相連多格 = 一個大櫃位；同一字母分散多處 = 同一種東西有好幾個（例：好幾張桌子）。
每個有畫在地圖上的 zone 至少要有一格緊鄰地板，且從 `start` 走得到。請照真實店面動線配置（入口附近放什麼、收銀台在哪、冷藏櫃靠牆…）。

### 區域 zones
```js
A:{ type:'shelf', icon:'🍙', jp:'おにぎり・お弁当', kana:'おにぎり・おべんとう', zh:'飯糰・便當',
    loc:{ jp:'入口の右の棚です', kana:'いりぐちのみぎのたなです', zh:'在入口右邊的架子' } }
```
| type | 用途 | 必填 |
|---|---|---|
| `shelf` | 貨架：玩家自己拿商品 | `icon,jp,kana,zh,loc` |
| `machine` | 券売機／自動販賣機／售票機：投幣買 | `icon,jp,kana,zh,loc` |
| `menu` | 菜單分類（eat 用）。**不必畫在地圖上**，入座後翻菜單就會出現 | `icon,jp,kana,zh` |
| `counter` | 有店員的櫃台（收銀、點餐、服務台）。店員櫃台賣的東西（熱食、車票、備品）用說的買 | `icon,jp,kana,zh,loc,npc:{who:'店員',emoji:'🧑‍💼'}` |
| `seat` | 座位（eat 必須有）：入座 → 翻菜單 → 叫店員 | `icon,jp,kana,zh` |
| `facility` | 設施：廁所、ATM、置物櫃、試衣間…可以問在哪、問時間 | `icon,jp,kana,zh,loc`，可加 `tip`、`hours:{jp,kana,zh}` |
| `sign` | 牆上的看板、告示 | `jp,kana,zh`，可加 `style`、`note` |
| `deco` | 純裝飾（植栽、廚房） | `icon` |

`loc` 是店員回答「〜はどこですか」時說的話，要符合地圖上的實際位置，句尾用「〜です／〜にあります」。
每間店：8–18 個 zone，其中至少 1 個 `counter`、2 個 `sign`、1 個 `facility`；`eat` 至少 1 個 `seat` 與 3 個 `menu`；`store` 至少 4 個 `shelf`。

### 商品 items（每間店 24–36 個）
```js
{ id:'onigiri-sake', jp:'鮭おにぎり', kana:'しゃけおにぎり', zh:'鮭魚飯糰', emoji:'🍙', price:160, c:'ko', zone:'A', tags:['food'] }
```
- `zone`：所屬區域 key（shelf／machine／menu／counter）。放在 `counter` 的東西 = 要跟店員開口要（熱食、香菸、車票、飯店備品、借用品）。
- `price`：日圓，用真實行情；免費的備品填 0。
- `c` 量詞：`tsu` つ（餐點、通用）`ko` 個 `mai` 枚（票、衣服、薄的）`hon` 本（瓶、傘、細長）`hai` 杯 `satsu` 冊 `nin` 人前 `soku` 足 `chaku` 着 `hako` 箱 `fukuro` 袋 `sara` 皿 `dai` 台 `haku` 泊 `kai` 回 `mei` 名。省略 = `tsu`。
- `tags`：自訂標籤，給 `asks.when` 判斷（例：`warm` 會被問要不要加熱）。車票／目的地請加 `dest`（句型會變成「〜まで〇枚」）。
- `jp` 不要有括號註記；口說和標示不同時加 `say:{jp,kana}`。
- 同一間店內 `id`、`jp` 不可重複。

### 店員問句 asks（每間店 5–8 個）
```js
{ id:'heat', phase:'pay', when:'tag:warm', zh:'要不要加熱',
  v:[ ['温めますか。','あたためますか'], ['こちら温めますか。','こちらあたためますか'], ['お弁当は温めましょうか。','おべんとうはあたためましょうか'], ['温めはいかがなさいますか。','あたためはいかがなさいますか'] ],
  a:[ { val:'yes', jp:'はい、お願いします。', kana:'はい、おねがいします', zh:'好，麻煩你', brief:'要加熱' },
      { val:'no',  jp:'いいえ、大丈夫です。', kana:'いいえ、だいじょうぶです', zh:'不用了', brief:'不用加熱' } ],
  bad:[ { jp:'いただきます。', kana:'いただきます', zh:'我開動了', fb:'這是吃飯前說的，不是回答要不要加熱' } ] }
```
- `phase`：`enter` 進店帶位｜`order` 點餐時追問｜`pay` 結帳｜`checkin` 櫃台辦手續（入住、報到、租借）。
- `when`：`always` 或 `tag:<標籤>`（籃子／點單裡有該標籤的商品才問）。
- `v`：同一個意思的 **3–5 種說法，由簡單到敬語**（N5 只會聽到第 1 種，等級越高越後面）。
- `a`：玩家可選的正確回答，1–3 個；`brief` 是任務單上的中文需求（6 字內）。`val` 在同一題內不可重複。
- `bad`：1–2 個「日文正確但場合不對」的回答＋`fb` 說明為什麼不對。
- 每間店至少要有一題付款方式（`id:'pay'`，`a` 至少 2 種）。`eat` 要有 `enter`（幾位）與 `pay`（一起／分開結）；`service` 要有 3 題以上 `checkin`。

### 可以拜託的事 acts（2–4 個，て形）
`{ id:'heat', jp:'これを温めて', kana:'これをあたためて', zh:'把這個加熱', re:{ jp:'かしこまりました。', kana:'かしこまりました', zh:'好的' } }`
引擎會接成「〜ください／〜もらえますか／〜いただけますか」。

### 可不可以 may（2–4 個，て形）
`{ id:'photo', jp:'写真を撮って', kana:'しゃしんをとって', zh:'拍照', ok:false, re:{ jp:'申し訳ございません、店内は撮影禁止です。', kana:'…', zh:'抱歉，店內禁止攝影' } }`
引擎會接成「〜もいいですか」。`ok` 請照真實規矩（至少 1 個 true、1 個 false）。

### 可以問的事 info（3–5 個）
```js
{ id:'hours', q:{ jp:'何時まで開いていますか。', kana:'なんじまであいていますか', zh:'開到幾點？' },
  re:{ jp:'二十四時間営業です。', kana:'にじゅうよじかんえいぎょうです', zh:'24 小時營業' },
  opts:['24 小時營業', '開到晚上 12 點', '早上 6 點開門'] }   // 第 1 個是正解，其餘 2 個是聽錯會選的
```

### 劇情委託 quests（每間店 2–3 個，真實情境）
```js
{ id:'night', title:'深夜抵達，肚子好餓', zh:'旅伴：幫我買唐揚便當和一瓶茶，便當要加熱，我沒帶購物袋。',
  jp:'からあげ弁当とお茶を買ってきて。お弁当は温めてね。袋もお願い。', kana:'…',
  items:[ ['bento-karaage',1], ['ocha',1] ], prefs:{ heat:'yes', bag:'yes', pay:'cash' } }
```
`items` = [商品 id, 數量 1–3]；`prefs` = { 問句 id: 要回答的 val }（只需列任務在意的）。`jp` 是旅伴用日文傳來的訊息（朋友口吻，N3 以上會只顯示日文）。

### 對話 dialogues（沒有 `scene` 的店必填 1 段，6–8 輪；有 `scene` 可省略）
```js
{ title:'結帳', steps:[ { speaker:'店員', emoji:'🧑‍💼', jp:'…', kana:'…', zh:'…',
    choices:[ { jp:'…', kana:'…', zh:'…', correct:true, feedback:'為什麼對' }, { …, correct:false, feedback:'為什麼不對' } ] } ] }
```
每步 3 個選項，可以有 1–2 個 correct。輪到玩家主動開口時，`speaker:'你'`、`emoji:'🙋'`、`jp:'（中文情境說明）'`、`kana:''`。

## 文字規則
- 說明、`zh`、`tip`、`fb` 用**繁體中文（台灣用語）**。
- `kana` 是整句的平假名讀音（片假名詞也寫成平假名，英數照念法寫，例 ATM → えーてぃーえむ）；可保留「、」。
- 日文用店員／旅客實際會說的自然說法；金額、營業時間、規矩要符合現實。
- 檔案是純 JS 物件，字串用單引號；字串內的單引號改用全形或「」。
