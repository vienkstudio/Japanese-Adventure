### 2.3 先修關係（P0：使用者回報「推薦跳過先修」的根因）
1. **N3–N1 有 233 條沒有任何先修**，推薦／路線把它們當「可直接學」。
2. build 用 `pre.ord < self.ord` 過濾，同級但原始順序在後的先修會被**靜默刪除**，而不是把順序調整成拓撲序。
3. 8 條先修指向不存在的條目（〜ほど、〜後で、〜ところだ、〜以上は 等寫法不符）。
4. `kb.js nextGram()`：從「使用者等級以上」找第一條未學，**完全不看 pre**；N3 使用者會直接被推 N3 第一條，即使 N4 先修沒學。
5. `mind3d.js nextOf()`：只在勾選等級裡找第一條未學，同樣不看 pre；路線模式的「下一步」與任務「路線推進 ×5」「每日」都沿用它，錯誤一路傳下去。
6. `mind-game.js pick({order:'ord'})`：按 ord 取未學，不檢查先修。
7. 知識庫項目頁「先學」只列清單、不顯示是否已會，提示文字還寫「僅供參考」。

## 3. 修正方案（已實作）

### 3.1 資料（`tools/build-mind.mjs` 重跑產生 `data/mind/*`）
- `GLV_FIX`：2.1 的 6 條改級。
- `GALIAS`：2.2 的 21 條刪除，所有 pre／rel 引用改指保留條目；另把不存在的寫法（〜ほど→〜ほど〜ない、〜後で→〜た後で、〜ところだ→〜るところだ、〜以上は→〜以上（は））對應好。輸出 `M.GALIAS`，`kb.js` 啟動時把舊 id 的已學／收藏／最近狀態搬過去。
- 先修補齊：N4 以上無先修者，優先取「相近(rel)」中較低級條目（最多 2 條），否則取同類別在最近較低級的第一條（`preAuto:1` 標記，207 條）；規則找不到的 9 條用 `GPRE_ADD` 手動指定（〜って（主題）←は、〜合う／〜直す←〜ます…）。
- 先修只允許同級或更低級；**同級改用 Kahn 拓撲排序**（優先原順序）後重編 `ord`，不再靜默刪邊；偵測到環會警告並斷邊（目前 0）。
- 分類：`fixScene` 讓「其他」桶裡 wh=地→新場景「🧭方位位置」、wh=時→時間日期、wh=人→溝通社交；「其他」改名「抽象概念」（264→216）；`LEX_FIX` 修 10 條 wh。

### 3.2 推薦邏輯
- `kb.js gramPath(lvs, n)`：依 `ord`（＝等級→先修拓撲序）走目標等級，遇到目標有未「已掌握」的先修，就把整條未學先修鏈（含較低等級）依序排在前面。`nextGram`、3D `nextOf`、任務 `pick` 全部改走它。
- 下一步卡若推到低於使用者程度的先修，顯示「要學『X』得先會這條」與「我已會 Nx 以下文法」（一次標記，含確認）。
- 項目頁「先學」已會的打 ✓，標題顯示「還差 n 條」。
- `mind-game pick`：限類別／變化時，先修已會的排前、沒會的排後。
- 3D 圖例：焦點模式加場景、文法類別、變化形；路線模式加「下一步／未學（淡）」；桌機顯示「層：下 N5 → 上 N1」。

## 4. 驗證
- `node tools/build-mind.mjs`：727 條、刪重複 21、自動補先修 207，無 gpre／grel／gcycle 警告。
- 拓撲檢查：每條 pre 的 ord 皆小於本身（0 違規）。
- 無頭 Chrome 375px：N3 使用者第一次推薦為 N5「は」（〜ようとする 的先修鏈起點）；按「我已會 N5」→ 推 N4 〜（よ）う；再按 N4 → 推 N3 〜ようとする。`App.go('kb')`、`App.go('mind3d')` 四種模式 console 0 錯誤。
