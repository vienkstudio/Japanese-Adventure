## ② 前 8 個問題

**1. 高｜問句套用到不合適的品項，店員還照樣回答**
- 證據：js/world.js:833 和 850–854 把所有 items 都套進「有沒有…／在哪裡」的範本。
- 實測：上野站→問店員→有沒有…？→秋葉原，組出「すみません、秋葉原はありますか」，站員回「はい、ございます。入口を入って右です」（截圖 20-akiba-reply.png）。
- 「在哪裡？」選秋葉原，會回答「秋葉原は、入口を入って右です」。
- 修法：items 依 tags 過濾。dest 類的品項改用「〜へ行きたいです／〜は何番線ですか」；have/where 只列出實際物品和設施。

**2. 高｜手冊缺最常用的旅遊句，也查不到冒險世界的內容**
- 證據：搜「多少錢／ikura」只出現「入場料はいくらですか」，沒有「これはいくらですか」。
- 「退稅、信用卡、儲值、素食、不要辣、打包、發票、怎麼去、中文菜單、一位」都顯示 0 筆。
- 冒險世界資料其實有這些詞：退稅 2 檔、信用卡 4 檔、打包 5 檔。
- 原因：js/phrasebook.js:6–13 只讀 SCENES 的 11 個場景，沒有讀 data/world。
- 修法：
  - 手冊索引加入 WORLD 各店的 acts/may/info/asks 句子。
  - 補必備句：これはいくらですか、カードで、免税、持ち帰り、ベジタリアン。
  - 加同義詞表：儲值=加值=チャージ、退稅=免稅、外帶=打包。

**3. 高｜手冊不顯示羅馬拼音，完全沒學過的人讀不出來**
- 證據：js/phrasebook.js:58 的 row() 只顯示 jp、kana、zh。資料裡其實有 romaji（scenes-1/2/ext 共 837 筆），甚至有諧音 hint（scenes-2.js:273），而且 :69 的搜尋也用到 romaji。
- 修法：assist='full' 或 lv=zero 時，在 kana 下面加一行 romaji；📢 全螢幕也一起顯示。

**4. 中｜組句只接受一種詞序**
- 證據：js/phrase.js:123 的 accept 只排列品項組，數量和收尾固定；:174 判「順序不對」。

② 前 8 個問題

1. 【高】返回鍵回不到日本地圖
- 證據：js/world.js:1040-1051，`play` 沒帶參數時會用 `world.at` 自動回到上次位置。
- 操作：play（地圖）→ play{r:tokyo,d:ueno} → 便利商店 → 按返回 → 到上野 → 再按返回，應回地圖，結果還是上野（60-back-to-map.png）。從首頁 → play{} → 店，按返回也一樣停在原店（s6 測試）。
- 修法：歷史紀錄裡的 `play{}` 一律畫地圖，只有首頁「繼續冒險」才帶 `{r,d,s}`。或者第一次轉址時用 `history.replaceState` 把真正參數寫回該筆紀錄。

2. 【高】首次開啟就下載 5.1MB，延遲載入在流量上等於白做
- 證據：sw.js:3-11 的 `FILES` 預先快取 77 檔，實測 cache 達 5111KB（vendor/3d-force-graph 1.4MB、mind 856KB、world 1.5MB）。
- 修法：預快取只放外殼和首頁必需檔（約 300KB），其餘靠 fetch 的「用過才快取」（現有 handler 已會 put）。

3. 【高】首頁同步載入約 680KB，其中大半是舊模組
- 證據：index.html:39-42 與 52-56。首次載入 32 個請求、1041KB 未壓縮，DOMContentLoaded 約 2.4 秒（本機）。
- `MENUS`（64KB）只有 practice/town 用；舊模組 quest+practice+town+travel 約 176KB。
- 修法：menus 與舊模組改用 `App.lazy`（`trip`/`menu`/`drill`/`practice-map`…），travel 資料只交給 `World.loadEvents` 載。

4. 【中】旅程資料被載入兩次，記憶體裡有兩份不同的 TravelData
- 證據：index.html:40-42 已同步載入，js/world.js:49 的 `loadEvents` 又用 `loadScript` 注入一次。實測 DOM 有兩組 data/travel*.js 的 script。
- js/travel.js:3 在載入當下就解構 `{levels, stops}`，所以 travel.js 拿舊物件，world-quest 拿新物件。
- 修法：刪掉 index.html 的同步載入，或讓 `loadScript` 先檢查已存在的 `<script src>` / `window.TravelData`。

5. 【中】部分資料繞過 core 直接寫 localStorage，不進備份／雲端
- 證據：js/jp-text.js:409,411,698（`jpq.read.udict` 使用者自訂辭典）、js/songs.js:10,49,54（`jpq.song.pref`）。
- 違反 core.js:3 註解「不得直接改 localStorage」。`App.backup` 與雲端同步都不含這兩份，換裝置或還原就會遺失。
- 修法：併入 `App.state.read` / `App.state.song` 由 core 存；不想併入就改用 `App.store`，並在 backup 時一起打包。

6. 【中】migrate 沒驗證 xp 型別
- 證據：js/core.js:40-62 只補陣列和物件欄位。實測存檔 `xp:"abc"` 能原樣載入（30-badxp.png）。之後 core.js:204 的 `S.xp += n` 會變成字串相加 `"abc10"`，存檔永久壞掉。
- 舊玩家有 xp 但沒有 trip/world 時，`placed:false` 會被要求重新選程度（實測 xp:500 出現首次選擇畫面）。
- 修法：`st.xp = Number.isFinite(+st.xp) ? Math.max(0, +st.xp) : 0`，`cleared` 若是陣列就重設為 `{}`，`profileFromOld` 在 `xp>0` 時也設 `placed:true`。

7. 【中】死碼與舊模組邊界不清
