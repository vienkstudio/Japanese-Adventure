## P0：會教錯

### 1. 斷詞給錯讀音，旅遊必用詞也錯（`js/jp-text.js` `tokenize`）
歌詞、新聞、閱讀、匯入歌曲的「每詞讀音＋中文」都用這套。實測：

| 原句 | 顯示 | 正確 |
|---|---|---|
| 生ビール | 生(**せい**) | なま |
| 日本酒 | 日本(にほん)＋酒(**さけ**) | にほんしゅ |
| お腹が空いた | 空いた(**あいた**) | すいた |
| こっちの方がいい | 方(**かた**)＝位（敬） | ほう |
| 雨が降りそうです | 降り(**おり**)＝下（車） | ふり／降る |
| 会議は三時に開かれます | 開かれます(**あかれます**) | ひらかれます |
| 四月一日に出発します | 一日(**いちにち**)＝一天 | ついたち |
| 一日中雨だった | 中(**なか**) | じゅう |
| 今日は何曜日 | 何(**なに**) | なん |
| 別れは辛い | 辛い(**からい**)＝辣 | つらい |
| 窓を開けてください | 開く／**可能形** | 開ける |
| 彼は来ないそうだ／飲み込んでしまいそうな | そう＝**是的** | 傳聞／樣態 |
| プレゼント用に | 用＝**事情** | 〜用（用途） |

- 正解大多已經在 `alts` 候選裡（上表加 * 的），只是第一候選選錯。
- 改法：
  - 加一層「上下文規則」，在選第一候選前套用：
    - 前面是「雨／雪が」時，降り選降る。
    - 「〜の方が」「〜方がいい」的方讀ほう。
    - 日期（〇月＋一日）讀ついたち；「〇日中」的中讀じゅう。
    - 何＋曜日／人／時／回讀なん。
    - 「は／が」後面的辛い讀つらい，食物名後面讀からい。
    - お腹が空く讀すく，席／部屋が空く讀あく。
  - 複合詞先查整詞：生ビール、日本酒、生卵、生放送。
  - 動詞連用形後面的そう、ように，第一候選改成文法（樣態、目的），不要當單字。
  - 把上表全部加進 `tools/`，做成斷詞回歸測試。

### 2. 學習紀錄用「字面」當 id，同形異讀互相蓋掉，有詞永遠教不到（`js/learn.js:20` `jp0`、`:298`）
- id＝`'v:' + jp0(jp)`，讀音不算在內。8,034 詞裡有 **199 組** id 撞在一起。今日課在 `:298` 用 `!isFresh(id)` 跳過，所以只要學過其中一個，另一個就不會再出。
- 會漏教的例子：
  - 同在 N5：一日（いちにち／**ついたち**）、九（きゅう／**く**）、〜時（じ／**とき**）、キロ（**公斤／公里**）、〜中（じゅう／ちゅう／なか）。
  - 跨級：開く（N5 あく → N4 **ひらく**）、辛い（N5 からい → N3 **つらい**）、方（かた → **ほう**）、角（かど／すみ／かく／つの）、上（うえ／じょう／うわ／かみ）、来る（くる → N1 きたる）。
- 複習也一樣：答對「ひらく」會被記成「あく」也會了。
- 改法：id 改成 `v:jp|kana`，例如 `v:開く|ひらく`。舊紀錄只有字面的，遷移時歸給該字面最低等級那一筆。`choice.js:132`、`path.js:196`、`practice.js:384` 也要一起改。

### 3. 詞庫原始格式漏到畫面上（`lex-*.js` 欄位沒清乾淨，6 套清理函式各清各的）
- 字面含分號的有 23 筆，例如「足; 脚」「キロ; キログラム」「堅; 硬; 固い」「(花を〜) 生ける, 活ける」。讀音欄含註記的有 18 筆，例如「けっこん (する)」「いく; ゆく」「なん; なに」「まいげつ; まいつき」「(〜を) とお」。
- 讀音欄放成漢字：`いただく|頂く`（N4）。動詞讀音帶註記：「こす (みずを～)」等 8 筆（N1）。
- 漏出來的地方：
  - `learn.js:299/461/562` 只去括號、沒切分號，今日課會出現「いく; ゆく」「まいげつ; まいつき」這種讀音。
  - `practice.js:384` 完全沒清，字卡直接顯示「足; 脚」「けっこん (する)」，id 是 `word:足; 脚`。
  - 「回る、回す」用頓號，所有 `jp0` 都不會切開。
- 改法：在 `tools/build-mind.mjs` 產生資料時就拆好欄位，jp 一個主形加 `alt[]`，kana 一個主讀加 `altKana[]`，註記另放 `note`。前端 6 份 `jp0`（choice、kb、mind3d、lookup、learn、activity）和 `jp-text.js:415 clean` 合成一個 `App.lexForm()`。

### 4. 場景資料錯字（`data/scene-ext.js:160`）
- 「これは子供も飲めますか」的讀音寫成「これはこども**もも**のめますか」，多了一個も。TTS 用讀音念，所以會念錯。
- 中文寫「這個小孩也能**吃**嗎」，但原句是飲めます（喝、服用）。

## P1：會記錯、看不懂

5. **諧音提示 741 處，會養成錯的發音**
   - 長音、促音、高低音都會丟掉，例如：信号＝「心狗」（沒有長音）、ラストオーダー、「摳勒哇 摳兜摸摸 諾妹媽斯卡」。
   - 零基礎已經有講義和訓練表，諧音反而跟它衝突。
   - 改法：諧音只留在五十音單字（あ＝阿）。句子層級全部拿掉，改成標示長音與促音（例如 しんごー、ラスト・オーダー）。
6. **羅馬字兩套寫法混用**
   - 837 筆裡有 214 筆用長音符號（dōzo、jūji、ōdā），95 筆用重複字母（pasuwaado、shingou、tooi、oukagai）。同一個「信号」在 scenes-2 寫 shingou，別處寫 shingō。
   - 另有 maccha（Hepburn 寫 matcha）。
   - 改法：資料裡的 romaji 一律由 `Phrase.romaji(kana)` 產生（biz 已經這樣做），手寫欄位刪掉。
7. **常用假名詞顯示成罕見漢字**
   - N4「凄い」「事」，N3「在る; 有る」，N5「朝御飯」「伯父; 叔父さん」。
   - 字卡大字顯示漢字，但日本實際上幾乎都寫假名，學了反而認不出看板。
   - 改法：資料加 `usuallyKana` 旗標，或沿用 JMdict 的 uk 標記，顯示時改用假名主形。
8. **用語過時**：N4「看護婦＝護士」，現行用語是看護師。舊 JLPT 字表還有其他舊詞，應全部掃一遍。
9. **逐詞翻譯冒充整句翻譯**
   - 歌詞、新聞只有逐詞中文。助詞「に」一律顯示「在／往／給（時間、地點、對象」，連括號都沒閉合（`jp-text.js` 的 zh 被截斷）。
   - 使用者拼不出句意，又會把「そう＝是的」「方＝位」這類第一義誤當答案。
   - 改法：
     - 補上截斷的括號。
     - 助詞與文法詞只顯示「（文法）」，點開才看說明。
     - 整句中文沿用歌詞來源的翻譯，或在匯入時讓使用者自己貼。沒有整句翻譯時，要明說「逐詞參考，不是整句翻譯」。
10. **同一個意思有多種說法**（掃描 `js/`，數字是出現次數）

    | 概念 | 說法 |
    |---|---|
    | 卡片 | 字卡 44／卡片 25 |
    | 詞 | 單字 106／詞彙 22／生詞 1 |
    | 考試 | 測驗 40／小考 22／挑戰 59／模擬考 9 |
    | 練 | 練習 54／訓練 22／特訓 18 |
    | 退出 | 返回 37／離開 33／關閉 19／✕ 24／← 13 |
    | 讀音標示 | 羅馬字 33／**拼音** 7（拼音是中文用語，零基礎會以為是注音或 pinyin） |
    | 貨幣 | 円 21／日圓 11 |

    改法：寫一份用語表（CONTRACT.md 附錄），每個概念只留一個說法；離開鍵只留 ←。
11. **樣式沒有收斂**
    - 13 個 css 檔、434 種色碼、34 種圓角、22 處 <14px 字、JS 內 133 處 inline style、24 份 `esc` 定義。
    - 結果就是 v15 各角色說的「商務卡、今日課卡、旅遊卡長得不一樣」，以及特大字切版。
    - 改法：定 `--c-*`、`--r-*`、`--fs-*` 三組 token，新程式碼禁用色碼和 px 字級（加到 `tools/` 的 lint）。

## P2
- `lex-n4` 與 `lex-n3` 的「運転」重複，中文不同（駕駛／駕駛；運轉）。
- 「アイス」在場景同時是「冰淇淋、冰品」和「冰的」。
- N3 以上的旅遊狀況題，題目本身（場景說明）也是日文。這對 N3 合理，但第一次進 N3 時沒有提示。
- 干擾項規則（`choice.js:76`）有排除同讀音、同義，算嚴謹。但讀音題的假字干擾項（げんってん）仍是 v15-06 提過的問題。

## 對抗結論
- 最大風險不在介面，在**語言正確性**：斷詞和讀音是全站共用的底層，一錯就同時出現在歌詞、新聞、今日課與查頁。生ビール、日本酒、お腹が空いた這類旅遊第一天就用到的詞也念錯。
- 第二大風險是**學習紀錄 id 設計**：199 組同形詞互相遮蔽，課程會無聲地漏教，使用者和開發者都看不出來。
- 介面問題（用語、樣式）是長期累積的債，不會教錯，但讓 9 位角色都覺得「每個模組像不同 App」。

建議優先順序：P0-1 上下文讀音規則＋回歸測試 → P0-2 id 加讀音 → P0-3 建置時拆欄位 → P0-4 錯字 → P1-9 逐詞翻譯標示 → P1-6 羅馬字統一 → 其餘。
